# 六项核查与上下文防误判

本文件用于「按使用者自己的规则复核」阶段（尤其是低频打开岗位页、公司页与评价页时）的核查方法。这六项是**核查方法，不是六条默认排除规则**；实际接受与排除标准仍以使用者自己明确确认的规则（或明确选用的经验包项目）为准。

## 1. 岗位详情：薪资结构

- 分别记录招聘薪资区间、固定底薪、绩效、提成/分成、补贴与试用期差异；只写页面能确认的数额与条件，没写的标「未说明」，不推算到手工资。
- 综合薪资和最高收入不能当成固定底薪；绩效/补贴是否有达成条件不靠猜测。
- 列表页与详情页、正文中多处口径不一致时，同时列出原文与来源，不用较高的一项覆盖较低的一项。
- 只有使用者已明确不接受某种结构或设定了金额下限时，才按其规则排除；未设要求时只说明结构与未核信息，不因看到“提成/绩效”就自动淘汰。

## 2. 阅读职责：名称与实际工作

- 从 JD 的具体任务、考核指标与技能标签提炼 1–2 个主要职责，对照使用者目标。例如标题叫“行政助理”、职责却以客户开发和销售业绩为主，要直接指出实际工作内容，不只凭岗位名归类。
- 主要工作与偶尔协助分开；没有标注比例时不编造百分比。
- 标题与内容不一致本身只作说明和核查重点，按使用者已确认的职责偏好判断，不擅自新增排除条件。

## 3. 对照背景：资格差距

- 逐项对比学历、专业、对口经验、技能与证书要求，区分要求强度：**必须要求 / 一般要求 / 优先或加分**。普通要求不自动升级成硬门槛，“优先”不直接当作硬性不符。
- 同一要求重复表达只计 1 次（例如“本科”与“本科学历”不算两项）。
- 未知学历、未说明年限、未确认是否持证，属于「信息不足」，不算已知不符；不从学校/专业猜学历，不把总工作年限当成对口专业年限，不把参加过培训当成取得证书。
- 若使用者选择了按差距数量提醒或排除，明确不可缺少的硬资格仍须单列，不用其他优点掩盖。

## 4. 判断规则：措辞与完整上下文

作息、加班、压力、业务性质等判断必须读完整短句与上下文，分清肯定、否定、条件、举例和描述对象：

- **加班**：区分「无需加班」「不强制加班，忙时配合」「必须接受加班」；否定前缀和条件状语必须保留，不抓单个词下结论。
- **作息**：「单双休 / 大小周 / 轮休」不能因为包含“双休”两个字就当成双休；两个平台网页都可能漏标双休，未标注不等于不符合。
- **服务对象与公司性质**：「为某行业客户提供服务」只说明客户类型，不能直接证明招聘公司本身属于该行业。
- **抗压表述**：「有一定抗压能力」等概括要求与明确高压、持续超负荷分开，按使用者自己的接受度判断。

## 5. 查询公司：资料交叉核对（Boss直聘 · 智联招聘）

- 对照公司简介中的主营/兼营业务、已读在招职位、平台展示的工商字段（如有）和行业标签，用一句大白话说明公司大概做什么。
- 注明每项信息来自哪个平台、哪天读取，区分「平台展示 / 企业自填」与「综合资料判断」；只是推测的要标明「推测」，不当成确认事实。
- **双平台差异留意**：
  - Boss直聘公司页通常不展示注册资本、登记地址、成立日期等完整工商字段，缺字段属于平台未展示，不凭此判为空壳或问题公司。
  - 智联招聘公司页通常展示工商信息及少量内嵌评价，完整评价在职Q页（`zq.zhaopin.com/companyDetail/公司编号`），评价总数大于已读条数时须点进并滚到底读全再下结论；未读全须标明覆盖范围（已读几条 / 共几条）。
  - 智联单岗未写双休/作息时，可看同公司其他在招职位标题是否标注「双休」作线索（但同公司他岗写了双休不代表当前岗一定一样，仍需注明来源）。
- 行业标签可能是企业自填，经营范围不等于实际主业；品牌简称与工商登记主体名称不一致时保留差异说明，不强行合并；工作地与工商登记地址严格分开。
- 评价是发布者主观陈述，不写成已证实的客观定论；同一条评价里提到多个问题只算 1 次，低分也不直接等于特定负面。

## 6. 去重与交付：相似岗位差异

- `jobscan.py` 已在列表阶段过滤「同公司同岗位（含词序变体与 Boss 福利后缀）」并单独输出「同公司标题相近的」对比表。
- 深核时如发现同公司相近岗位都值得比较，补充对比已读到的职责侧重、薪资口径、工作地点、经验要求与招聘人；缺哪一项就写「未读到／无法确认」，不把未读部分说成相同。
- 交付给使用者的清单须按使用者**全部已启用规则**复核过；未核完的标明缺项和待核原因，不写「核查通过」。
