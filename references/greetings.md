# 整理招呼语规范

当使用者要求在筛选、复核后为合适岗位配招呼语时执行本规范。**AI 只负责撰写与对照，永远不点「立即沟通」「投递」，不上传简历，也不查看或回复聊天消息。**

## 1. 先取得必要信息（底线与授权边界）

- **先读已存档案，不重复讨要固定经历**：动笔前先运行 `python3 jobscan.py profile`。里面已经记着用户的学历、做过哪些事、经历要点时，**直接沿用，不再重复贴一遍或重新答**；新问到的固定学历、做过的事与经历要点，确认后用 `profile set` 补进 `data/profile.json`。
- **不擅自读取简历**：默认不打开在线简历、不搜电脑里的本地文件。
- **缺背景时先说明用途，再给三选一（单选）**：说明提取经历只用于对照岗位要求写招呼语，不用于代投。
  1. 回答几个具体问题（由助手按求职方向给出带例子的具体事项）
  2. 自己上传简历或粘贴经历片段（可隐去姓名、电话、住址等敏感信息）
  3. 明确授权读取当前已登录平台的在线简历（**只有用户明确选第 3 项或直接开口授权时才只读打开**；仅列在选项里、沉默或只说“帮我写招呼语”都不算授权）
- **简历不是必需材料**：选第 1 项答几个具体问题即可；实在不愿提供简历或详细经历时，仍可按已知事实帮写简短、礼貌的岗位意向招呼语，但绝不捏造匹配点，也不称为个性化文案。
- **写任何招呼语前，必须先确认两项**（本轮已明确且仍有效的直接沿用；跨天新对话里即使 `profile.json` 记过上次状态，也只用一句话轻确认是否变化）：
  1. **当前就业状态**（用具体选项区分，不用含糊的“尚未就业”）：
     - 在校，准备找实习或工作
     - 已毕业，目前没有工作
     - 正在实习
     - 正式在职，考虑换工作
     - 已离职，目前没有工作
  2. **预计可到岗时间**：用户说不确定就如实留白，**不能从离职日期或应届身份推断并承诺“随时到岗 / 立即到岗”**。
- **学历补问边界**：只对**刚毕业的应届生或正在找实习**且现有材料未写明学历的用户用自由文字补问一次（「你的学历是什么？直接打字告诉我就行」）；毕业已久的用户不主动追问学历，也不从专业/学校猜学历。
- **提问要具体**：不问「你有什么技能」「你想突出什么」这类空问题。针对求职方向列出 4–6 件具体的事做多选（如「用表格整理名单/账目」「做会议记录」「接待与电话咨询」「采购登记」等，末项为互斥的「都没做过」），选过后再问有没有一件能具体说出来的事。用户说没做过的绝对不写进文案；课程作业、校园实践、兼职如实标注，不写成正式全职经验。

## 2. 按岗位组织内容（防套模板与防串稿）

- 从当前岗位 JD 提取 1–2 个核心要求，对应已知真实经历，写 3–4 句自然简短的招呼语即可，不堆砌无关经历。
- **同时投基础岗与主管/经理岗时分开写**：
  - 专员/助理/文员等基础执行岗：突出对应具体事务、熟悉的工具/流程和可独立完成的事项，不硬把管理头衔塞在开头。
  - 主管/经理等管理职责岗：突出真实承担过的管理范围、团队协调、流程搭建或业务结果；**没有正式管理经历只能写项目统筹、协作或带教，不能升级成“带团队/部门管理”**。
  - 先读实际 JD 判断职责，不只看岗位名（有些“客户经理”是纯执行，“主管”也可能是不带人的独立岗）。
- **事实准确性**：
  - 有可靠数字才写数字（保留范围与个人贡献，参与不改写成主导）；没有数字就写清做法和产出，**不编百分比或夸大效果**。
  - 不把总工作年限当成某个垂直方向的对口年限。
  - 少写「高度匹配」「执行力强」「充满热情」等空洞套话；不替用户承诺加班或降薪；不写尚未发生的「已发送简历」。

## 3. 交付与对应检查

- **一一对应相邻呈现**：每个合适岗位按「`原序号` 公司 / 岗位 → 岗位链接 → 对应可复制招呼语」紧挨着展示，避免一长段话原样套给多个岗位。
- **匹配说明放在文案外**：需要解释“为什么这样写”或提醒待确认的事项，放在可复制招呼语之外，不要混进发给 HR 的正文里。
- **待核与排除边界**：缺关键核查项的待核岗位如果提前附了文案，须保留未核完提示，不能因附了招呼语就称“已合格”；已排除岗位不附招呼语。
- 使用者自己审阅、修改并发送；只有使用者明确告知已发送/已投递后，才执行 `applied add` 记账，生成文案本身不计为已投。
